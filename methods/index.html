Methods guide

从导入文献到导出 PRISMA 材料，每一步都能回头核对。From imported records to PRISMA exports, each step stays easy to check.

第一次接触系统综述的同学可以先用 Demo 熟悉流程；正式项目从数据库导出的 CSV、RIS、NBIB 或 ENW 文件开始。工作台会保留来源、去重、筛选决定和导出记录，方便你和导师、同伴或审稿人一起核对。项目记录默认保存在当前浏览器；需要分享时由你主动导出文件。Students new to systematic reviews can start with the demo. Formal projects usually begin with CSV, RIS, NBIB, or ENW exports from databases. The workspace keeps source, deduplication, screening decisions, and export records connected so you can review them with supervisors, teammates, or peer reviewers. Project records are saved in the current browser by default; you share them by exporting files.

第一次使用，可以这样走A simple first path

先看懂流程，再换成自己的数据库导出文件。Learn the flow first, then switch to your own database exports.

Step 1

用 Demo 先跑一遍Try the demo first

Demo 不需要准备文件，适合快速了解导入、去重、筛选和导出按钮在哪里。The demo needs no files and helps you find the import, deduplication, screening, and export steps.

Step 2

导入自己的检索结果Import your search results

从 PubMed、EndNote、Zotero、CNKI、万方、维普或其他数据库导出文件后，在工作台里核对题名、作者、摘要、年份和来源字段。After exporting records from PubMed, EndNote, Zotero, CNKI, Wanfang, VIP, or another database, check title, author, abstract, year, and source fields in the workspace.

Step 3

筛选、复核并导出Screen, review, and export

完成标题摘要筛选、全文复核和质量评价后，导出 PRISMA 计数、决定表、排除理由和复核材料。After title/abstract screening, full-text review, and quality appraisal, export PRISMA counts, decision tables, exclusion reasons, and review materials.

流程里会留下哪些记录What the workflow records

这些记录帮助你在写方法部分、组会汇报或回应审稿意见时说明过程。These records help you explain the process in methods sections, lab meetings, or reviewer responses.

来源SourceImport

每条记录来自哪个文件Which file each record came from

导入时会保存来源文件、解析格式、来源数据库和文件级记录数。中文来源中的摘要截断、摘要噪音或字段映射问题会作为提醒保留。Imports keep source file, parser format, source database, and file-level record counts. Chinese-source truncation, abstract noise, and mapping gaps are kept as warnings.

去重DedupReview

硬重复和疑似重复分开处理Hard and candidate duplicates stay separate

明显重复可以自动移除；相似但需要判断的记录会进入候选重复列表，方便人工核对。Clear duplicates can be removed automatically; similar records that need judgement remain in the candidate-duplicate list.

决定DecisionLedger

筛选结论和理由可追溯Screening decisions and reasons are traceable

纳入、排除、不确定、排除理由、复核者和时间会进入决定表和事件日志，PRISMA 计数可以回到这些记录核对。Include, exclude, uncertain, exclusion reason, reviewer, and timestamp go into decision tables and event logs, so PRISMA counts can be checked against them.

复核ReviewA/B

双人复核保留 A/B 和合并结果Dual review keeps A/B and final values

Reviewer A 和 Reviewer B 可以分别记录决定；项目负责人合并文件后，冲突队列和一致性指标会重新计算。Reviewer A and Reviewer B can record decisions separately. After file merge, conflict queues and agreement metrics refresh.

双人复核怎么交接How dual-review handoff works

适合两位同学或两位复核者在不同电脑上各自筛选，再把结果交给项目负责人合并。Use this when two reviewers work on separate computers and send their results back to the project owner.

Collaboration Seed

项目负责人先导出一个起点文件，复核者用它建立相同项目上下文。The owner exports a start file so reviewers can open the same project context.

Reviewer Decision Bundle

Reviewer A 或 B 完成筛选后导出自己的决定文件，里面只包含对应复核者的决定。Reviewer A or B exports a decision file after screening; it contains only that reviewer scope.

合并与核对Merge and check

合并前会检查项目、记录、复核者范围和重复导入状态；通过后刷新冲突和一致性指标。Before merge, the workspace checks project, records, reviewer scope, and duplicate import state, then refreshes conflicts and agreement metrics.

可以导出哪些材料What you can export

导出文件在本地生成，适合先自己核对，再放入方法附录、团队交接或审稿回复。Exports are generated locally. Review them first, then use them in methods appendices, team handoff, or reviewer responses.

project_manifest.json

记录项目名称、PRISMA 版本、AI 模式、应用版本和导出时间，方便确认这份导出来自哪个项目。Records project name, PRISMA version, AI mode, app version, and export time so you can identify the project source.

export_snapshot_manifest.json

列出导出包中的文件名、媒体类型、字节数和 SHA-256，用来核对一组导出文件是否保持一致。Lists filenames, media types, byte counts, and SHA-256 values so an export set can be checked for consistency.

方法附录 / 复核证据包Methods appendix / review package

汇总 PRISMA 计数、筛选决定、双审冲突、质量评价、来源提醒和 AI 使用记录。Summarizes PRISMA counts, screening decisions, dual-review conflicts, quality appraisal, source warnings, and AI-use records.

AI 在这里扮演什么角色What AI does here

当前公开工作流以人工决定为准，AI 默认关闭。The public workflow treats human decisions as authoritative, and AI is off by default.

AI 建议会记录在独立的 suggestion log 中。只有人工接受或改写后写入 `ScreeningDecision`，才会影响 PRISMA 计数；被拒绝或暂时忽略的建议只作为辅助记录保存。AI suggestions are recorded in a separate suggestion log. They affect PRISMA counts only after a human accepts or edits them into `ScreeningDecision`; rejected or ignored suggestions remain advisory records.

真实 AI 服务需要用户主动配置。默认状态下，工作台不会自动发送文献内容或密钥。A real AI provider requires explicit user setup. By default, the workspace does not send record content or keys automatically.
