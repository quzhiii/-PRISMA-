E4Workflow

工作流完整性Workflow integrity

双审冲突、一致性指标、Reviewer Bundle round-trip、重复导入拒绝和 Export Snapshot hash 都有自动化测试。Dual-review conflicts, agreement metrics, Reviewer Bundle round-trip, duplicate import rejection, and Export Snapshot hashes are covered by automated tests.

数据保真协议Data fidelity protocol

每一步都保留来源、解析和人工决定之间的可追溯关系；提醒不会静默改写记录或决定。Each step keeps the traceable relationship between source, parsing, and human decisions; warnings do not silently rewrite records or decisions.

来源层Source layer

文件与来源元数据一起保留Files stay linked to source metadata

导入记录保留来源文件、解析格式、来源数据库和文件级记录数；项目清单与导入事件记录来源文件的增加和移除。Imported records retain source file, parser format, source database, and file-level record counts; the project manifest and import events record source-file additions and removals.

解析层Parsing layer

保留字段，显式标记不确定性Fields are preserved; uncertainty is explicit

CSV、RIS、NBIB、ENW 采用流式解析；中文来源字段映射、摘要疑似截断、摘要噪音和来源映射不完整会进入记录或审计提醒，不伪装成完整字段。CSV, RIS, NBIB, and ENW use streaming parsers; Chinese-source mapping, suspected abstract truncation, abstract noise, and incomplete source mapping become record or audit warnings rather than being presented as complete fields.

决定层Decision layer

警告与决定分开Warnings stay separate from decisions

来源质量提醒不会自动创建或改变 `ScreeningDecision`。人工决定、排除理由、双审冲突和 resolver 结果分别进入决定表、事件日志和 Reviewer Bundle。Source-quality warnings do not automatically create or change a `ScreeningDecision`. Human decisions, exclusion reasons, dual-review conflicts, and resolver outcomes remain represented in decision tables, event logs, and Reviewer Bundles.

导出与复核合同Export and review contracts

导出文件是本地生成的证据材料，供研究者核对后用于方法附录、团队交接或审稿回复。Export files are local evidence materials for researcher review before methods appendices, team handoff, or reviewer responses.

project_manifest.json

保留项目元数据：项目名称、PRISMA 版本、AI 模式、应用版本和导出时间。它不是完整导出集合的完整性清单。Keeps project metadata: project name, PRISMA version, AI mode, app version, and export time. It is not the integrity manifest for the complete export set.

export_snapshot_manifest.json

绑定 M5 本地导出集合：每个 artifact 的文件名、媒体类型、字节数、SHA-256、artifact set hash 和 manifest hash。Binds the M5 local export set: filename, media type, byte count, SHA-256, artifact-set hash, and manifest hash for each artifact.

Reviewer Bundle

Seed 和 Decision Bundle 用于双审文件交接，不是在线协作服务。错误项目、篡改内容、错误 reviewer scope 和重复 bundle 会在 merge 前被拒绝。Seed and Decision Bundles support dual-review file handoff, not an online collaboration service. Wrong projects, tampering, wrong reviewer scope, and duplicate bundles are rejected before merge.

AI 边界AI boundary

当前公开工作流以人工决定为准，AI 默认关闭。The current public workflow treats human decisions as authoritative, and AI is off by default.

AI 建议记录在独立的 suggestion log 中。只有人工接受或改写后写入 `ScreeningDecision`，才会影响 PRISMA 计数；被拒绝或忽略的建议只保留为辅助记录。AI suggestions are recorded in a separate suggestion log. They affect PRISMA counts only after a human accepts or edits them into `ScreeningDecision`; rejected or ignored suggestions remain advisory records.

当前不默认连接真实 AI 服务，也不自动发送文献内容或密钥。任何未来服务接入都需要单独说明数据边界。The current default does not connect to a real AI provider or automatically send record content or keys. Any future provider connection needs a separate data-boundary explanation.

已知限制Known limits

这些限制保留在公开说明中，避免把当前能力说成更强的保证。These limits remain visible so current capabilities are not overstated.

没有云端项目状态No hosted project state

当前不提供账号、云端项目查询或实时同步；跨设备协作依赖本地 JSON 文件交接。There are no accounts, hosted project lookup, or real-time sync; cross-device collaboration relies on local JSON file handoff.

导出需研究者核对Exports require researcher review

PRISMA 计数、质量评价和 GRADE 摘要是可复核材料，不替代研究方案、全文判断或方法学审查。PRISMA counts, quality appraisal, and GRADE summaries are reviewable materials, not replacements for protocols, full-text judgement, or methodological review.

外部验证仍在计划中External validation remains planned

当前公开证据来自仓库测试、fixture 和基准文档；真实脱敏项目和用户测试不会在完成前被宣传为既有结果。Current public evidence comes from repository tests, fixtures, and benchmark docs; real de-identified projects and user tests are not presented as completed until they exist.
