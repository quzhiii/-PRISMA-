当前可用的协作流程Current collaboration flow

完整项目保存/加载仍是单独的备份路径；下面的 Reviewer Bundle 只处理复核交接。Full-project save/load remains a separate backup path. Reviewer Bundle files handle review handoff only.

STEP 01

Collaboration Seed

项目负责人在已有本地项目中导出 Collaboration Seed，复核者导入该文件建立独立上下文。Seed 使用 `reviewer_bundle.v1.local` + `m4.v1` 合同，包含 SHA-256 来源清单、记录数量和记录 hash。The project owner exports a Collaboration Seed and the reviewer imports it to create an independent context. The Seed uses the `reviewer_bundle.v1.local` + `m4.v1` contract with SHA-256 source-manifest, record-count, and record hashes.

STEP 02

Reviewer Decision Bundle

Reviewer A 或 B 在自己的项目上下文中记录决定，并导出只包含其复核值的 Decision Bundle。导入前会验证 reviewer ID、项目 ID、记录 hash、决定 hash 和重复导入状态。Reviewer A or B records decisions in the independent context and exports a scoped Decision Bundle. Import validates reviewer ID, project ID, record hash, decisions hash, and duplicate-application state.

STEP 03

Merge importMerge import

项目负责人将 Bundle 导入现有项目；非法修改、缺失记录、错误项目和重复 Bundle 会先被拒绝，合法 Bundle 才会刷新冲突队列、一致性指标和导出门禁。The owner imports the Bundle into the existing project. Tampering, missing records, wrong projects, and duplicate bundles are rejected before valid bundles refresh conflicts, agreement metrics, and the export gate.

边界说明Boundary

项目 ID 只是本地项目标识，不是网络地址。应用不会在服务器上查找该 ID，也不会自动等待另一位复核者的数据。A project ID is a local identifier, not a network address. The application does not look it up on a server or automatically wait for another reviewer's data.
