Dual-review file handoff

两位复核者可以用本地文件完成独立筛选交接。Two reviewers can hand off independent screening with local files.

适合一位项目负责人和两位复核者分工：负责人导出起点文件，Reviewer A / B 各自筛选，再把决定文件交回合并。整个交接过程不需要注册账号。Use this for one project owner and two reviewers: the owner exports a start file, Reviewer A / B screen separately, then return decision files for merge. The handoff needs no account.

三步完成文件交接Three-step file handoff

如果你只是想备份整个项目，请使用工作台里的项目保存；这里主要用于 A/B 复核结果交接。For a full-project backup, use project save in the workspace. This page focuses on A/B review handoff.

STEP 01

Collaboration Seed

项目负责人从已有项目导出 Seed，发给 Reviewer A / B。Seed 会带上项目和记录校验信息，包括 `reviewer_bundle.v1.local`、`m4.v1` 和 SHA-256 记录 hash。The owner exports a Seed from the project and sends it to Reviewer A / B. The Seed carries project and record checks, including `reviewer_bundle.v1.local`, `m4.v1`, and SHA-256 record hashes.

STEP 02

Reviewer Decision Bundle

Reviewer A 或 B 在自己的电脑上完成筛选后，导出只属于自己的 Decision Bundle。文件会标明复核者、项目、记录和决定 hash。Reviewer A or B screens on their own computer, then exports a Decision Bundle for that reviewer only. The file records reviewer, project, record, and decision hashes.

STEP 03

Merge importMerge import

项目负责人导入 Decision Bundle 后，工作台会检查项目、记录、复核者范围和重复 Bundle，再刷新冲突队列、一致性指标和导出状态。After the owner imports a Decision Bundle, the workspace checks project, records, reviewer scope, and duplicate bundles, then refreshes conflicts, agreement metrics, and export state.

协作提示Collaboration note

项目 ID 用来确认文件属于同一个本地项目。请通过导出的 JSON 文件交换结果，并在合并后查看冲突队列和一致性指标。The project ID confirms that files belong to the same local project. Exchange results through exported JSON files, then review the conflict queue and agreement metrics after merge.
