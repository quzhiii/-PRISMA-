# PRISMA 项目体检 / 迁移 / 审计包

英文辅助名称：PRISMA Project Health Check / Migration / Audit Pack

这是一项面向系统综述和 Meta 分析项目的受控试点服务：把混乱的数据库导出、既有筛选状态和双审记录，整理为可以复查的 PRISMA counts、去重风险、冲突摘要和方法附录证据材料。

## 一句话价值主张

如果你的系统综述项目已经有 PubMed、CNKI、万方、维普、SinoMed、Excel 或 Rayyan 导出，但去重、筛选记录、双审冲突或 PRISMA counts 说不清，我们帮助你把过程整理成可复查、可交接、可用于组会 / 答辩 / 方法附录讨论的证据包。

## 典型痛点

- 多个数据库导出的字段不一致，中文摘要、作者、期刊或 DOI 信息混乱。
- Excel、Rayyan 或旧表格中已有筛选状态，但难以迁移、复查或解释。
- 自动去重不放心，担心误删，也担心候选重复没有被记录。
- PRISMA 图里的数字和实际筛选表对不上。
- 双人复核有分歧，但缺少清晰的冲突清单、agreement 摘要和最终决定记录。
- 导师、课题组、答辩委员或审稿人追问流程时，缺少可复查证据。

## 适用客户

- 医学、护理、公卫、循证医学研究生。
- 正在进行系统综述或 Meta 分析的小课题组。
- 已经存在 PubMed、CNKI、万方、维普、SinoMed、Excel 或 Rayyan 导出材料的项目。
- 需要整理导入、去重、筛选状态、双审冲突和方法附录证据的团队。

暂不适合只有一个研究想法、尚未形成检索结果、或希望代写综述结论的项目。

## 需要提供什么

- 原始数据库导出文件，如 NBIB、RIS、ENW、CSV、TSV、BibTeX、RDF、TXT。
- 如果已有筛选工作，请提供 Excel、Rayyan 导出或其他筛选状态表。
- 研究主题、PICO/PICOS、纳入排除标准和时间范围。
- 已使用的排除理由字典或导师 / 课题组要求。
- 如有双人复核，请提供 Reviewer A / B 的决策记录和当前冲突状态。
- 如有质量评价，请提供已有质量评价表、工具族或评价备注。

在发送文件前，需要先完成 intake，确认你有权提供这些数据，并确认数据处理边界、存储路径、访问人员和删除期限。

## 能拿到什么

标准交付物会根据 intake 后的实际范围确认，通常包括：

- 导入与字段质量摘要。
- 去重风险和候选重复清单。
- PRISMA counts。
- 筛选状态恢复或迁移说明。
- 双审冲突与 agreement 摘要。
- Defense-ready Audit Pack。
- 方法附录草稿。
- 交接说明。

这些材料用于帮助你复核、交接和解释项目过程，不替代你或方法学专家作出最终研究判断。

## 工作流程

1. 初步沟通：确认项目类型、当前材料和最痛问题。
2. Intake 检查：确认数据权利、来源、文件规模、敏感信息和交付边界。
3. 导入与字段检查：整理来源、字段质量、缺失项和中文源可靠性提示。
4. 去重与筛选状态整理：区分硬重复、候选重复、已有筛选状态和迁移风险。
5. 双审与质量评价检查：如项目涉及双审或质量评价，整理冲突、agreement 和缺口。
6. 审计包与方法附录：生成或整理 PRISMA counts、Defense-ready Audit Pack 和方法附录草稿。
7. 交接说明：说明结果、风险、需要你确认的决定和下一步。

## 试点边界

- 试点交付周期将在完成 intake 后确认；2-3 个工作日仅作为标准小项目的待验证目标。
- 标准小项目通常指来源文件和记录规模有限、字段可映射、已有规则较清晰的项目。
- 如果记录数、来源数量、表格混乱程度或时间要求超出试点范围，需要重新确认范围。
- 当前交付周期、规模和价格都属于待验证假设，不能视为稳定承诺。

## 为什么需要人工确认

系统综述中的最终纳入、排除、质量评价和 GRADE 判断都属于研究判断。工具可以帮助整理数据、暴露风险、生成证据包和记录过程，但不能替你决定一篇文献是否最终纳入，也不能替代导师、课题组或方法学专家的判断。

需要人工确认的内容包括：

- 候选重复是否合并或保留。
- 旧筛选状态是否正确映射到新项目。
- 排除理由是否符合你的研究方案。
- 双审冲突的最终决定。
- 质量评价 judgement、supporting quote、页码和证据等级。
- 方法附录文字是否符合你的真实流程。

## 客户配合事项

- 提供合法来源的原始导出文件，不只提供二次编辑后的截图。
- 提供当前使用的纳排标准、排除理由和项目背景。
- 对候选重复、冲突记录和方法附录草稿进行确认。
- 不发送无权分享的全文、账号凭证、机构访问权限或敏感个人信息。
- 如项目有紧急截止日期，请在 intake 阶段说明。
- 如果希望使用任何远程 LLM、Agent、第三方 API 或云端服务处理原始数据，必须先单独书面授权；默认不会这样处理。

## 不包含什么

- 不提供数据库授权绕过、机构账号使用、全文抓取或自动下载。
- 不替客户做最终纳入、排除和质量评价判断。
- 不替代方法学专家、导师或课题组决策。
- 不保证投稿、答辩或发表结果。
- 不提供结论代写、Meta 分析统计、临床结论或治疗建议。
- 不提供云端多人协作平台、账号系统、支付系统或机构部署。

## 拒绝交付条件

- 客户无法确认自己有权提供数据。
- 文件包含不可分享的个人敏感信息、受限制内容或账号凭证。
- 客户要求绕过数据库授权、抓取全文或处理未经授权的材料。
- 客户要求服务方替代最终研究判断或承诺发表 / 答辩结果。
- 项目规模、时间要求或数据混乱程度明显超出试点边界，且客户不接受重新定范围。

## 隐私和本地处理说明

- PRISMA Workbench 的核心工作流默认本地优先，客户资料不需要默认上传到云端。
- 真实客户资料不会进入公开 Git 仓库或公开 demo。
- 客户原始数据默认不会发送给远程 LLM、Agent、第三方 API 或遥测服务。
- 客户资料默认存放在 Git 仓库和云同步目录之外。
- 详细安全条款会在 intake 阶段确认，包括文件清单、SHA256、处理工具、访问人员、保留期限和删除记录。
- 如需保留脱敏结果用于产品改进，必须获得客户明确允许。

## 独立项目免责声明

本服务基于独立开源工具和人工交付流程，不是 PRISMA Statement 官方产品、认证或背书。PRISMA 是系统综述报告指南，本服务只帮助整理和复查流程证据，不保证研究结论或发表结果。

## 如何开始试点

请先用 3-5 句话说明：

- 你的研究主题和项目阶段。
- 当前有哪些导出文件或筛选表。
- 记录量大概有多少。
- 你现在最担心的问题是什么：导入、去重、PRISMA counts、双审冲突、方法附录，还是其他问题。

收到初步信息后，会先做 intake 检查，再确认是否接受试点、交付范围和预计周期。
