# PRISMA 商业验证操作首页

本目录用于受控验证 `PRISMA 项目体检 / 迁移 / 审计包`（PRISMA Project Health Check / Migration / Audit Pack）。它是内部商业验证材料，不是官网、正式定价页或公开营销页。

## 验证目标

- 完成 5 个真实系统综述 / Meta 分析项目交付。
- 获得至少 2 个复盘时仍有效、未全额退款、未取消的真实付款或定金项目；书面意向和口头意向单独记录，但不得等同真实付款。
- 验证客户是否愿意为导入质量、去重风险、筛选状态迁移、双审冲突、PRISMA counts 和 Defense-ready Audit Pack 付费。
- 记录每次交付的人工耗时、失败点、客户价值、价格反应和下一步。
- 在验证完成前，不实现支付、账号、license、云同步、数据库抓取或产品锁。
- 在验证完成前，客户原始数据默认不得发送给远程 LLM、Agent、第三方 API 或遥测服务。

## 材料使用顺序

1. `SERVICE_OFFER.md`：私发给潜在客户的一页式服务说明。
2. `INTAKE_CHECKLIST.md`：客户同意试点后，用于确认数据权利、项目范围和处理边界。
3. `SAMPLE_DELIVERY_GUIDE.md`：用公开 demo 解释样例交付物，不使用真实客户数据。
4. `VALIDATION_RECORD_TEMPLATE.md`：每次访谈、试用或真实交付后填写一份匿名验证记录。
5. 本文件：用于内部复盘验证进度、Go / Pivot / Stop 信号和未验证事项。

## 客户触达前检查项

- 确认当前触达对象属于目标客户：医学、护理、公卫、循证医学研究生，或正在做系统综述 / Meta 分析的小课题组。
- 确认对方已有 PubMed、CNKI、万方、维普、SinoMed、Excel 或 Rayyan 导出材料，而不是只有一个泛泛选题。
- 明确说明这是独立工具和人工服务，不是 PRISMA 官方产品或认证。
- 明确说明不替代方法学专家，不替客户做最终纳入、排除和质量评价判断。
- 不承诺固定交付周期、正式价格、投稿结果、答辩结果或发表结果。
- 不接收未经授权的数据、受限制全文、个人敏感信息或无法说明来源的资料。
- 在客户发送文件前，先用 `INTAKE_CHECKLIST.md` 确认数据存放位置和处理边界。

## 每次交付后必须记录的证据

- 匿名 validation_id、日期、客户类型和获客渠道。
- 项目类型、数据库来源、文件数量、记录数和原使用工具。
- 客户原始痛点、原本解决方式、最重视的交付物和不理解的交付物。
- 测试服务包、测试报价、付款状态（全款 / 定金 / 未付款 / 退款）、金额、币种、折扣、付款日期和脱敏付款证据编号。
- 书面意向和口头意向分别记录；它们只能作为意向信号，不能计入真实付款主指标。
- 只有复盘时仍有效、未全额退款、未取消的全款或定金项目，才能计入真实付款主指标。
- 全额退款、取消订单、口头意向和书面意向不得计入 Go 的真实付款数量；退款和取消仍应保留为商业验证证据，用于分析产品、价格或交付失败原因。
- 实际交付内容、实际人工耗时、导入失败点、字段问题、候选重复数和冲突数。
- 是否用于组会、答辩、投稿、方法附录或内部复核。
- 对价格的反应、是否愿意推荐、是否愿意复购、是否允许匿名引用。
- 主要证据路径、下一步、Go / Pivot / Stop 信号和复盘结论。

## 客户数据边界

- 客户数据不得进入公开 Git 仓库。
- 不在 `docs/`、`tests/`、`fixtures/`、`literature-screening-v2.2/` 或任何会被提交的路径下保存客户文件。
- 客户数据默认存放在 Git 仓库和云同步目录之外；准确存储路径、同步 / 备份状态、访问人员和处理工具必须在 intake 中记录。
- 客户原始数据默认不得发送给远程 LLM、Agent、第三方 API 或遥测服务。
- 如需例外，必须记录客户书面授权、工具 / 服务商、数据范围、用途、保留期限和删除期限。
- 每个输入文件必须登记文件别名、大小和 SHA256；不得用客户姓名命名文件或证据路径。
- 交付记录中只保留匿名编号、脱敏摘要和必要证据路径，不记录真实姓名、手机号、邮箱、付款账号或可直接识别客户的数据。
- 如客户允许保留脱敏结果用于产品改进，也必须在 `VALIDATION_RECORD_TEMPLATE.md` 中记录授权范围。

## 可发给客户的材料

- `SERVICE_OFFER.md`：可私发，作为试点服务说明。
- `SAMPLE_DELIVERY_GUIDE.md` 中经过人工整理后的公开 demo 截图或样例目录说明：可私发，但必须标注为公开模拟数据。
- 根据 `docs/templates/audit-appendix-template.md` 改写的项目专属方法附录草稿：仅可发给对应客户。

## 仅供内部验证的材料

- 本文件。
- `INTAKE_CHECKLIST.md` 的内部判断部分。
- `VALIDATION_RECORD_TEMPLATE.md`。
- 报价实验假设、Go / Pivot / Stop 判断和客户价值复盘。

## 内部报价实验假设

以下为内部报价实验假设，不是已验证市场价格，不得直接发布到官网。

| 服务类型 | 内部测试区间 | 说明 |
|---|---:|---|
| 单项目体检 | ¥499-¥999 | 适合已有导出和筛选表，需要快速定位导入、去重、PRISMA counts 和审计风险的小项目。 |
| 迁移 + 审计包 | ¥1,500-¥3,000 | 适合需要从 Excel、Rayyan 或混乱表格迁移，并生成可复查交付物的项目。 |
| 课题组试点 | ¥5,000-¥12,000 | 适合 2-6 人团队，需要双审、冲突整理、交接说明和方法附录材料的试点。 |

报价必须结合 intake 后的记录数、来源数量、表格质量、双审状态和时间要求单独确认。

## Go / Pivot / Stop 简表

| 判断 | 信号 | 下一步 |
|---|---|---|
| Go | 5 个真实交付中至少 2 个复盘时仍有效、未全额退款、未取消的真实付款或定金项目；客户明确使用审计包、迁移说明或冲突摘要；标准项目人工耗时可控。 | 固化服务包、完善样例交付、再决定是否产品化某些高频步骤。 |
| Pivot | 客户愿意为人工整理或中文源清洗付费，但不想购买软件；客户只需要方法附录、模板或迁移服务。 | 将 PRISMA Workbench 定位为内部交付工具，优先沉淀服务 SOP 和模板。 |
| Stop | 5 个高质量交付后仍无付款意愿；客户认为现有免费工具足够；真实数据兼容成本不可控。 | 暂停商业化投入，只保留开源工具和有限维护。 |

## 当前未验证事项

- 客户是否愿意为 Defense-ready Audit Pack 单独付费。
- 个人用户、课题组和机构用户中，哪个客户类型付款意愿最强。
- 中文源清洗、双审冲突整理、方法附录草稿和模板包之间，哪个价值最直接。
- 标准小项目是否可以稳定控制在 2-3 个工作日内完成。
- 真实项目中的字段缺失、编码问题、旧表格映射和双审身份混乱会消耗多少人工时间。
- 当前报价区间是否过高、过低或需要改成按项目复杂度报价。
- 客户是否愿意允许匿名引用交付结果用于后续产品验证。
- 客户是否接受“不发送远程 LLM / API、默认仓库外存放、交付后按期删除”的安全边界。
